# 怎样观察这四个系统

这是一次小型机制观察，不是四个纯 planner 算法的公平性能排名。普通模式是主条件，显式 Plan 模式是独立条件。各系统的后端模型、工具和提示词通常不同。第一轮各跑一次，理解过程；需要谈稳定性时，再为每个系统从相同初始版本重复 3 次。即使每个系统 3 次，也只是探索性结果，不能据此证明成功率不下降。

## 四类记录

| 类别 | 记录事实 | 不要据此声称 |
|---|---|---|
| decomposition | 明示计划、Todo、子任务顺序、并行委派、计划更新 | 没显示计划就没规划；列清单就是独立搜索算法 |
| action | 工具名称、参数、读了哪些文件、返回内容范围 | 模型比较过所有路线；选中的路线一定最省 token |
| feedback | 某个真实报错/测试结果之后，下一行动和代码如何变化 | 自动重试请求就是任务层重规划 |
| completion | 最后检查、完成声明、运行终止原因、独立验收 | turn.completed / Todo 全勾选就是任务正确 |

用 observations.csv 的 trace_locator 填会话消息号、JSONL 事件序号或截图名。每条事实都应能回到原始记录。把 observer_inference 与 observed_action 分开，避免把猜测当日志事实。不要记录、索要或假定能获得完整隐藏推理。

## 选择点

重点找这些局部选择：搜索定位或读取整个项目；只读几条样例或把日志全塞进上下文；靠可见样例推导一个小计或写一个临时脚本核算；修改后先跑一个失败测试或全量重测；保存短摘要或反复读取相同输出。

整个任务要修改文件，因此无法“全程纯内部推理”。你的 internal / external / hybrid 研究应先选定一个具体子问题和相同输入，再做路线干预及成本对比。没调用工具不等于观察到了内部推理预算；一个 Python 工具调用也可能包含大量前置模型推理。

## 怎样看反馈调整

按真实先后顺序摘取“命令 → 返回错误 → 阅读/修改 → 重测”。已有回归测试为失败反馈提供机会，但 agent 可能直接修好；这时写“未观察到失败后调整”。不要临时给某一个系统制造额外错误。

可选 Stage B 在 Stage A 结束并验收后发送 researcher/FOLLOWUP.md。它提供一致的需求变更，能观察计划更新和回归验证；它不等同于执行失败反馈。Stage A、B 单独记分，保留同一会话来观察延续行为。

## 怎样看完成

先保存 agent 自己的结束声明与它运行的验证，再由研究者运行外部 evaluate.py。分别记“模型声称完成”“验收检查通过”“停止原因”。不把预算用完或请求失败标记为成功。任务的成功口径是 Stage A 或 Stage B 所有验收检查通过；passed_checks/total_checks 是定位问题的检查通过率，不是任务成功率。

## 如何看实现

先观察一条真实行为，再查对应的官方源码或文档。例如看计划工具是仅保存模型给出的列表，还是会自己调度；看测试输出是直接返回模型，还是触发固定规则；看停止事件有没有配置额外检查。只有公开证据足够时才归因。提示词、框架控制和模型决策应分开记录。闭源内部细节写“未公开/未确认”。

## Token 统计的两个层次

1. 样例 JSONL 中的 token 是本任务的输入数据，具有人工定义的规范；它们不是测试 agent 的真实消耗。
2. Claude/Codex/DSH/Qoder 执行这次任务的真实 token 来自各系统的 usage。记录计量口径，缺失写 N/A，不要用字符数或工具次数冒充真实 token。

在不同系统之间，tokenizer、cache、reasoning、压缩、重试、子 agent 计量可能不同；先保留原始字段与来源，不直接把最低数值解释成 planner 更好。要验证你的节省方法，后续应固定模型、同一框架、任务与预算，随机或配对比较路线并重复实验。

## 实验控制

每次用 prepare_run.py 创建新副本和新会话，固定同一任务说明。保持依赖和数据相同；记录模型与系统版本、推理强度、权限、扩展及额外指令。不要将前一个系统的修复结果给下一个。不要为这轮临时添加“每步解释”“必须使用子 agent”“必须调用工具”的指令。不要只在某个系统启用强制完成 hook。

默认统一预算 30 分钟，研究者到时手动停止并记 budget_stop。可先做一次不计分 pilot，再统一调整所有系统预算。权限确认只授权完成任务所需的项目内读写和本地 Python 执行；记录确认，不需要开放整个文件系统或关闭所有审批。

本地 researcher 与 workspace 的目录分开只是减少意外泄露，不是权限隔离。不要把整个实验包作为 agent 的项目打开；不要给 agent 看参考实现、验收脚本、标准答案或失败细节。正式盲测可使用单独容器/用户，只挂载 workspace；本包不提供安全隔离承诺。
